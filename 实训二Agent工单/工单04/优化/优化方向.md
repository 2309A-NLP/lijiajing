# 工单04 优化方向：基于 Agent 的基金数据问答系统

## 1. 数据源扩展与实时性
- **当前方案**：基于静态数据集/历史数据进行问答。
- **优化方向**：
  - 接入实时财经 API（如 Tushare、AKShare、东方财富接口），实现净值、持仓、经理信息实时更新。
  - 增加定时数据同步任务（Cron Job），确保本地数据库 T+1 更新。

## 2. NL2SQL 查询优化
- **当前方案**：依赖 LLM 生成 SQL 查询数据库。
- **优化方向**：
  - 引入 Schema-aware Prompt，将表结构动态注入上下文，提升 SQL 生成准确率。
  - 增加 SQL 沙箱校验机制，拦截危险操作（DROP/DELETE/UPDATE），仅允许 SELECT。
  - 对错误 SQL 实现自动修复重试（捕获 SQLite 报错 → 反馈给 LLM 修正）。

## 3. 可视化增强
- **当前方案**：以文本/表格形式返回查询结果。
- **优化方向**：
  - 集成图表生成模块（Matplotlib/ECharts），自动将净值走势、收益率对比转为折线图/柱状图。
  - 支持一键导出 PDF/Excel 分析报告。

## 4. 复杂推理与对比分析
- **当前方案**：单基金单维度查询。
- **优化方向**：
  - 支持多基金横向对比（收益率、夏普比率、最大回撤等指标并排展示）。
  - 引入 Agent 规划能力，将复杂问题拆解为多步查询（如“推荐三只近一年涨幅前十且回撤小于15%的混合基金”）。

## 5. 性能与缓存
- **当前方案**：每次查询直连数据库。
- **优化方向**：
  - 热点数据缓存（如热门基金基本信息），降低数据库 I/O 压力。
  - 复杂聚合查询增加预计算汇总表，响应时间优化至 <500ms。
