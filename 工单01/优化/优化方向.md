# 工单01 优化方向：基于 Agent 的智能记账本系统

## 1. 意图识别优化
- **当前方案**：基于正则表达式匹配关键词进行意图分类（记账/查询/统计）。
- **优化方向**：接入轻量级分类模型（如 `bge-m3` 或 `qwen2.5-0.5b`）进行语义意图识别，提升对模糊表达（如“我昨天吃火锅花了80”）的泛化能力，替代硬编码正则。

## 2. 数据库设计优化
- **当前方案**：单表 SQLite 存储，字段固定。
- **优化方向**：
  - 引入分类标签体系（餐饮/交通/娱乐等），支持多级分类。
  - 增加 `tags` JSON 字段，支持用户自定义标签。
  - 实现数据备份与恢复机制（自动导出 CSV/SQL）。

## 3. 多轮对话与上下文管理
- **当前方案**：单次请求处理单条记录，无上下文记忆。
- **优化方向**：
  - 引入短期会话状态机，支持补录缺失字段（如“金额是多少？”“什么类别？”）。
  - 集成 `mem0` 或本地向量库，实现长期记账习惯记忆（如自动关联常用商户类别）。

## 4. 容错与异常处理
- **当前方案**：LLM 解析失败时依赖固定兜底逻辑。
- **优化方向**：
  - 增加 JSON Schema 校验 + 自动重试机制，当 LLM 输出格式不合法时触发修正提示。
  - 金额/日期字段增加格式校验与自动修正（如“上周五”转为具体日期）。

## 5. 性能优化
- **当前方案**：每次请求均调用 LLM。
- **优化方向**：
  - 高频简单查询（如“今天花了多少”）走本地规则引擎，绕过 LLM 调用，降低延迟至 <200ms。
  - 引入查询结果缓存（Redis/SQLite），相同查询直接返回缓存。
